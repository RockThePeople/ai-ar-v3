# W29 — `derive_idempotency_key` 부착 (계약 필수화 대비)

## 붙였다 — **클라가 안 보내면 내용에서 유도한다**

`POST /v2/assets/{id}/edits` 에서 `idempotency_key` 가 없으면
`editreq.derive_idempotency_key(asset_id, base_version, raw_prompt, mask_voxels, seed)`
로 채운다. 실서버 실측:

```
키 없이 1회차 → job j-3a11d2d1be3e · key 70a57e6fa4ad7fd8
키 없이 2회차 → job j-3a11d2d1be3e · key 70a57e6fa4ad7fd8   ← 같은 잡
다른 지시     → job j-43fbc9e22531 · key 801c495b212be173   ← 갈린다
클라 키 지정  → client-key-1                                 ← 그대로 쓴다
```

🔴 **난수를 쓰면 재시도가 매번 새 잡이 되고, GPU 를 쓰는 편집에서 그건 곧 중복 실행이다.**
내용 파생이라 같은 요청은 같은 키, 다른 요청은 다른 키다.

🔴 **클라가 보낸 키는 덮지 않는다.** 덮으면 클라 쪽 재시도 추적이 깨진다.

⚠️ 계약이 이 필드를 **필수**로 바꿔도 여기는 안 깨진다 — 클라가 보내면 그것을 쓰고,
   없으면 유도할 뿐이다. **서버가 지어내는 값이 아니라 요청 내용의 함수**라
   "무엇을 재시도했는가" 가 흐려지지 않는다.

테스트 10건 (`test_idempotency.py`): 같은 내용 같은 키 · 다섯 필드 각각 바뀌면 다른 키 ·
**마스크 순서·중복은 키를 안 흔든다**(A5000 EDIT-API-SPEC 이 정렬 불필요·중복 허용이다) ·
라우트가 실제로 채우는가 · 재시도가 같은 잡을 쓰는가 · 클라 키가 이기는가.

## ⚠️ 부수로 잡은 것 — 테스트가 GPU 를 태우고 있었다

라우트 테스트가 편집을 POST 하면 **백그라운드 잡이 실제로 돈다** — LLM 호출 → t2i(28초)
→ 상류 GPU. 라우트가 무엇을 **접수했는가**를 재는 테스트에 그 실행은 필요 없고,
인터프리터 종료 시 데몬 스레드가 남아 무관한 `Fatal Python error` 까지 냈다(실측).

⇒ `JOBS_EXECUTE=0` 이음매를 넣었다. **기본값은 실행**이다 — 끄는 쪽이 명시적이어야
   운영에서 조용히 안 도는 일이 없다.

⇒ 그 바람에 뜻이 바뀐 테스트 하나(`surface_voxelize` 거부)를 **동기 지점**에서 재도록
   고쳤다. 비동기 잡으로 방어를 재면 타이밍에 기대게 된다 — 스키마가 막거나
   `require_slat_grid()` 가 막거나, 둘 중 하나임을 직접 확인한다.
