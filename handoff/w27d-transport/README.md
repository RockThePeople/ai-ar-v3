# W27 — 상류 사유 전파 · 저장소 스캔 의혹 종결

## ★ 저장소 O(자산) 스캔 — **의혹이 맞았다. 고쳤다**

`AssetStore._slots()` 가 요청마다 읽기 루트를 전부 훑고 `manifest.json` 을 파싱했다.

| | 전 | 후 |
|---|---|---|
| 순수 파일 읽기 | 0.012 ms | 0.012 ms |
| `STORE.chunk()` | **0.698 ms** (56배) | **0.070 ms** (5.7배) |
| 그중 `_slots()` | **89%** | 캐시됨 |
| HTTP 서버 처리 중앙값 | **7.84 ms** | **3.49 ms** |

무효화는 **읽기 루트의 mtime** 으로 한다. TTL 을 안 쓴 이유: 만료 전에는 새 자산이
안 보이고, 그 사이 404 가 나면 원인을 못 찾는다. 슬롯을 만들 때는 캐시를 즉시 버린다
(mtime 해상도에 기대지 않는다).

## ★ 병렬이 느리던 것이 뒤집혔다

같은 표본(moto-b 120청크 · 평균 14.4KB), `<GEN_HOST>` 로컬:

| | 전 | 후 |
|---|---|---|
| 직렬 keep-alive | 3.15 ms/청크 | 3.14 ms/청크 |
| 병렬 8 | 7.49 ms/청크 (**0.4배**) | **2.03 ms/청크 (1.5배)** |
| 병렬 16 | 7.49 ms | 2.89 ms (1.1배) |
| 병렬 32 | 7.65 ms | 2.94 ms (1.1배) |

⇒ **서버는 병목이 아니다.** 맥북이 네트워크에서 가른 값(연결 10ms · RTT+전송 16.5ms
= 26.5ms)에 비해 내 서버 처리는 **3.49ms** 다. 병목은 네트워크 왕복이고,
**클라 병렬화가 듣는다** — 이제 서버가 그걸 벌주지 않는다.

⚠️ **이 측정은 로컬이라 병렬 이득을 과소평가한다.** 로컬은 감출 RTT 가 없다.
   맥북 경로는 왕복 26.5ms 를 겹칠 수 있으므로 이득이 여기보다 크다.
⚠️ **8 을 넘으면 이득이 죽는다** (16·32 에서 1.1배). uvicorn 단일 워커 + GIL 이 천장이다.
   더 필요하면 워커를 늘리는 것이 3090 쪽 다음 수단이다 — **지금 필요하다는 근거는 없다.**
⇒ **번들은 여전히 논할 때가 아니다.** 계약에 없고, 병렬화만으로 989청크 × 26.5ms 를
   8겹치면 충분한지부터 맥북이 재면 된다.

## ★ 상류 사유 전파

앱에 `UPSTREAM_EDIT_FAILED 편집 제출 실패` 만 뜨고 **실제 사유가 없었다.**
실제로는 `409 VERSION_CONFLICT — base_version=1 은 커밋되지 않았다` 였다.
사유가 없으면 사용자는 재시도만 하고, **재시도로는 절대 안 고쳐지는 오류**다.

이제 상류 코드·메시지를 그대로 올린다 (`server/upstreamerr.py`):

```
409 {"error_code":"VERSION_CONFLICT","message":"base_version=1 은 커밋되지 않았다"}
  → error_code = UPSTREAM_VERSION_CONFLICT
    error      = "<EDIT_HOST> 편집 제출 실패 (409 VERSION_CONFLICT): base_version=1 은 …"
```

🔴 **출처를 접두사로 남긴다.** 상류 코드를 그대로 쓰면 `VERSION_CONFLICT` 가 3090 것인지
`<EDIT_HOST>` 것인지 화면에서 안 갈린다 — **고칠 사람이 다르다.**

⚠️ 상류가 JSON 을 안 줄 때도 있다 (실측: `500 Internal Server Error` 평문).
   그때는 지어내지 않고 `UPSTREAM_HTTP_500` + 본문 앞부분을 그대로 싣는다.

테스트 5건이 잠근다 (`test_upstreamerr.py`).
