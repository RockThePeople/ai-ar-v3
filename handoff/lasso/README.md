# 라쏘 입력 — slat 좌표 (3090 → 맥북)

맥북 라쏘가 입력으로 쓸 **slat 격자 좌표**다 (D58). `np.load()` 하면 끝난다.

```python
import numpy as np, json
coords = np.load("handoff/lasso/dragon-c.slat_coords.npy")   # (N,3) int16, 값은 0..63
spec   = json.load(open("handoff/lasso/dragon-c.slat_coords_spec.json"))
assert spec["grid_source"] == "slat_coords"      # 🔴 이 확인을 건너뛰지 마라
assert len(coords) == spec["voxel_count_total"]
```

| 자산 | 좌표 수 | bbox (x, y, z) | 용도 |
|---|---|---|---|
| `dragon-c` | 9,591 | [1,0,0]–[62,63,62] | 라쏘 **초기 검증용** (Dragon 갈래는 D56 으로 종결 — 참고 기록이다) |
| `moto-b` | 9,150 | [19,0,8]–[44,63,55] | **작업 2 본자산** — `Black Motorcycle with driver` |

## 🔴 이 좌표는 3090 이 계산한 것이 아니다

D34 가 확정한 대로 `.cbin` 에서는 slat 좌표를 **유도할 수 없다** — 두 번 시도해서 두 번
틀렸다 (dragon-c: 표면 복셀화 10,264 vs slat 정본 9,591). 그래서 이 파일들은 A5000 이
생성 때 남긴 `slat.safetensors` 원본에서 **그대로 뽑은 것**이다. 유도가 아니라 이송이다.

각 좌표 수를 그 자산 `manifest.json` 의 `voxel_count_total` 과 대조해 통과했다 (D28).
라벨만 믿지 않기 위한 검사이고, 어긋나면 `server/slatexport.py` 가 `NotSlatCoords` 를 던진다.

⚠️ **표면 복셀화를 마스크 좌표의 근거로 쓰지 마라** (D28). 참고로 moto-b 는 표면
복셀화가 9,118, slat 정본이 9,150 이다 — 32개 차이라 "비슷하니 같겠지" 로 넘어가기
딱 좋은 크기다. 같지 않다.

## 좌표계

slat 격자는 **Z-up** 이다. GLB(Y-up)와 섞지 마라 — 정본은
`server/pipeline/frames.py` 의 `GLB_TO_VOXEL` 이고, 디코더 native → 복셀 프레임은
**항등**이다 (D9-b). 이 파일의 좌표는 이미 복셀 격자 프레임이라 아무것도 걸지 않는다.

## moto-b 의 형태 — 라쏘가 노릴 자리

작업 2 의 관문은 "몸체와 바퀴가 구조적으로 구분되는가" 였고, 통과했다. 근거는
시선 방향 **두께**다 (실루엣은 투영이라 앞뒤가 겹쳐 하나로 보인다 — D19):

| 구역 | 칸 | 두께 중앙값 | 최대 |
|---|---|---|---|
| 앞바퀴 | 298 | **4** | 10 |
| 뒷바퀴 | 300 | **4** | 8 |
| 몸체·엔진 | 277 | **9** | 17 |
| 라이더 | 208 | 6 | 19 |

바퀴는 얇은 원반, 몸체는 그 2배 이상 두꺼운 덩어리다. 다만 **3D 연결성분은 1개**다 —
바퀴가 포크·스윙암으로 붙어 있으니 당연하고, "분리된 덩어리" 를 성분 분리로 읽으면
어떤 실제 오토바이도 통과하지 못한다. 프로필 실루엣에서 둘러싸인 빈칸은 23칸뿐이라,
**실루엣만 보고 바퀴를 자르려 하면 뒷바퀴가 몸체에 붙어 나온다.** 깊이·두께를 쓰라.

방향: 긴 축이 **y**(0–63, 앞→뒤), 높이가 **z**(8–55), 폭이 **x**(19–44).
